# Verifier conformance suite (v8.8.0, FR-C2)

Language-neutral cases for the reference verifier functions. Every port
runs each case and must produce exactly `expected`.

```
vectors/verifier/
  audit-trail/<case>.json   verifyAuditTrailIntegrity
  signature/<case>.json     verifyEnvelopeSignatureEd25519
  revocation/<case>.json    lookupRevocation
  keys/                     TEST KEYS (see keys/README.md)
  _meta.json                case index with descriptions
```

Each case file is:

```json
{ "case": "<name>", "kind": "audit-trail|signature|revocation", "input": { ... }, "expected": { ... } }
```

Inputs per kind:

| Kind | `input` | Call |
|------|---------|------|
| `audit-trail` | `{ trail }` | `verifyAuditTrailIntegrity(trail)` |
| `signature` | `{ envelope, public_key, options? }` | `verifyEnvelopeSignatureEd25519(envelope, public_key, options)` |
| `revocation` | `{ lists, signer_key_id, at }` | `lookupRevocation(lists, signer_key_id, at)` with `at` as the string |

`expected` is compared as JSON. Fields that are absent in `expected`
must be absent in the result, not `null`.

Runners:

- TS: `tests/integrity/verifier-vectors.test.ts` and `npx tsx scripts/verifier-runner.ts`.
- Go: `vectors/runners/go/verify/vectors_test.go` and `go run ./cmd/verifier-runner` (from `vectors/runners/go`).
- Parity: `npm run verifier:parity` diffs the TS and Go result manifests.

The suite is generated by `scripts/generate-verifier-vectors.ts` from
fixed seeds and literal timestamps. Do not edit case files by hand.
Change the generator and re-run it; `--check` reports drift.

Semantics, reason codes and the porting guide:
`docs/architecture/reference-verifier.md`.
